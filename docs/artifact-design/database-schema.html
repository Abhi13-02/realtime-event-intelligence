Low-Level Design · Database Schema

Realtime Topic Intelligence — schema reference

One PostgreSQL 15 database with pgvector. Seven tables run the crawl-to-alert pipeline; five more sit on top as an additive intelligence layer for sub-theme discovery and sentiment. Nothing here modifies the tables that came before it.

Core pipeline

Ingestion → dedup → matching → alert delivery. Rejected articles never reach Postgres; Kafka's 7-day retention on raw-articles is the raw layer.

users

core

Google is the only identity provider — no password_hash, no refresh tokens. Accounts are created just-in-time from google_sub, read off the NextAuth JWT on first sign-in.

ColumnTypeConstraintsWhat it means
idUUIDprimary key, default uuid_generate_v4()Uniquely identifies the account. Referenced by every other table that stores per-user data.
nameTEXTnot nullDisplay name, pulled from the Google profile at sign-in.
emailTEXTnot null, uniquePrimary contact address and login identifier — also where the 24-hour digest email is sent.
google_subTEXTuniqueGoogle's stable subject ID from the NextAuth JWT. Looked up on every request to recognize a returning user and to just-in-time create the row on first sign-in.
phone_numberTEXT—Where Twilio sends SMS alerts, if the user has opted into that channel on any topic.
created_atTIMESTAMPTZnot null, default now()When the account was first created — set once, on the just-in-time insert.
idx_users_email

sources

core

Admin-curated list of RSS feeds, Reddit, and Hacker News. Not user-configurable in v1; is_active is only true for sources with a live crawl task implemented.

ColumnTypeConstraintsWhat it means
idUUIDprimary keyIdentifies the feed. Every crawled article points back to exactly one of these.
nameTEXTnot nullHuman-readable label, e.g. "BBC News" — shown wherever a source is surfaced.
urlTEXTnot null, uniqueThe feed or API endpoint the ingestion service polls.
typeTEXTnot nullHow it's fetched — rss or api — so the crawler picks the right Celery task.
credibility_scoreFLOATdefault 0.5, check 0–1A trust weight for the source, shown to users for transparency. Copied onto each match but never factored into whether an alert fires.
poll_intervalINTdefault 600 (seconds)How often Celery re-polls this feed — 10 minutes by default.
is_activeBOOLEANdefault trueTurns crawling on or off. Only true for sources with a live crawl task actually implemented.
last_crawled_atTIMESTAMPTZ—Timestamp of the most recent successful poll — lets ops spot a feed that's gone silent.

topics

core

One row per user-defined topic. expanded_description — a Gemini expansion of name + description — is what Sentence-BERT embeds, not the raw name. sensitivity maps to a float threshold (0.55 / 0.65 / 0.75) inside the pipeline, never stored as a number here.

ColumnTypeConstraintsWhat it means
idUUIDprimary keyIdentifies this topic — the anchor for matches, alerts, and every sub-theme discovered under it.
user_idUUID→ users.id, not null, on delete cascadeWhose topic this is. Deleting the user deletes the topic and everything built on it.
nameTEXTnot nullShort label the user typed in, e.g. "generative AI regulation."
descriptionTEXToptional, user-providedExtra keywords or context the user gave to sharpen matching — the seed for the Gemini expansion.
expanded_descriptionTEXTGemini-generatedA fuller, LLM-expanded version of name + description — this is the text that actually gets embedded, not the raw name.
embeddingVECTOR(768)Sentence-BERT (all-mpnet-base-v2)The topic's position in embedding space. Every new article's embedding is compared against this to compute relevance.
sensitivityTEXTdefault 'balanced', check in (broad, balanced, high)User-facing alert strictness. The pipeline maps it to a similarity cutoff (0.55 / 0.65 / 0.75) that relevance_score must clear to alert.
is_activeBOOLEANdefault trueLets a user pause a topic without deleting its history.
created_at / updated_atTIMESTAMPTZupdated_at trigger-maintainedWhen the topic was created, and when it was last edited (name, description, or sensitivity change).
idx_topics_user_idtrigger: topics_updated_at

topic_idUUID→ topics.id, not null, on delete cascadeWhich topic this delivery preference belongs to.

articles

core

Only articles that survive stage-1 deduplication land here. pipeline_status tracks progress through the fail-fast pipeline; summary stays null until stage 5 (Gemini) completes.

ColumnTypeConstraintsWhat it means
idUUIDprimary keyIdentifies the article — referenced by matches, alerts, comments, and sub-theme memberships.
source_idUUID→ sources.id, not nullWhich feed this article was crawled from.
urlTEXTnot null, uniqueCanonical link to the original article — also the natural de-duplication key across re-crawls.
headlineTEXTnot nullThe article's title, shown in alerts and the dashboard.
contentTEXT—Full crawled body text, used as input to embedding and summarization.
summaryTEXTnull until stage 5Gemini-generated summary, produced once and reused for every user this article matches.
embeddingVECTOR(768)Sentence-BERT, used for dedupThe article's position in embedding space — checked against recent articles to catch near-duplicates and against topic embeddings to compute relevance.
pipeline_statusTEXTdefault 'passed_dedup', check in (passed_dedup, processed)How far this article has progressed through the pipeline — processed means it has a summary and has been matched against topics.
published_atTIMESTAMPTZ—When the source originally published the article, if known.
crawled_atTIMESTAMPTZnot null, default now()When this service ingested it — drives the "most recent first" ordering used across the app.
idx_articles_url idx_articles_source_id idx_articles_crawled_at desc idx_articles_embedding — ivfflat, cosine, lists=100

article_topic_matches

core

Junction table between articles and topics. credibility_score is copied from the source at match time for transparency only — alert checks compare relevance_score against the topic's sensitivity threshold and nothing else.

ColumnTypeConstraintsWhat it means
idUUIDprimary keyIdentifies this one article-topic pairing.
article_idUUID→ articles.id, cascadeThe article side of the match.
topic_idUUID→ topics.id, cascadeThe topic side of the match.
relevance_scoreFLOATnot null, check -1–1Cosine similarity between the article and topic embeddings — the number alert checks compare against the topic's sensitivity threshold.
credibility_scoreFLOATnot null, check 0–1Snapshot of the source's credibility_score at match time — shown for transparency, but never used to decide whether to alert.
created_atTIMESTAMPTZdefault now()When this match was computed.
unique (article_id, topic_id)idx_atm_article_ididx_atm_topic_id

alerts

delivery history

topic_id is intentionally denormalized here to avoid a join on every dashboard read. The unique constraint makes a replayed Kafka message from the pipeline a silent no-op rather than a duplicate alert.

ColumnTypeConstraintsWhat it means
idUUIDprimary keyIdentifies this one delivery attempt.
user_idUUID→ users.id, cascadeWho this alert was sent to.
article_idUUID→ articles.id, cascadeThe article the alert is about.
topic_idUUID→ topics.id, cascade — denormalizedWhich of the user's topics triggered it — duplicated here so the dashboard can read alerts without joining through article_topic_matches.
relevance_scoreFLOATnot null, check -1–1The score that cleared the sensitivity threshold, copied at send time so the alert shows why it fired.
channelTEXTcheck in (email, sms, websocket)Which delivery method carried this particular alert.
statusTEXTdefault 'pending', check in (pending, sent, failed)Delivery outcome — lets a retry job find and resend anything stuck at pending or failed.
sent_atTIMESTAMPTZ—When delivery actually succeeded, null until then.
created_atTIMESTAMPTZdefault now()When the alert was generated by the pipeline — the timestamp the dashboard sorts by.
unique (user_id, article_id, topic_id, channel) idx_alerts_user_id_created_at (composite) idx_alerts_status

Intelligence layer

Entirely additive — sub-theme discovery and sentiment tracking, built on top of the same articles without touching the tables above. A Celery job clusters news every 6 hours; Reddit is sentiment signal only, never embedded or matched to topics.

reddit_comments

intelligence

Linked to the article row representing the Reddit post. Used exclusively for VADER sentiment aggregation inside sub-theme discovery — never embedded, never used for topic matching, never surfaced as an alert on its own. score weights each comment in that aggregation.

ColumnTypeConstraintsWhat it means
idUUIDprimary keyIdentifies this one comment.
article_idUUID→ articles.id, cascadeThe Reddit post (stored as an article row) this comment was left on.
bodyTEXTnot nullThe comment text — fed into VADER to produce a per-comment sentiment score.
scoreINTdefault 0 — Reddit upvote scoreThe comment's upvote count, used to weight it in the sentiment aggregation — louder comments count for more.
created_atTIMESTAMPTZdefault now()When the comment was ingested.
idx_reddit_comments_article_id

sub_themes

intelligence

One row per discovered cluster within a topic — fully automatic, no user input. centroid lets Reddit posts join the nearest sub-theme by ANN search without re-clustering. status moves emerging → active → declining → inactive, driven entirely by env-var volume thresholds.

ColumnTypeConstraintsWhat it means
idUUIDprimary keyIdentifies the sub-theme — referenced by its memberships, snapshots, and any intelligence alerts it triggers.
topic_idUUID→ topics.id, cascadeThe parent topic this sub-theme was discovered within — clustering runs per topic, not globally.
label / descriptionTEXTnull until first LLM labeling (LangChain + Cohere)Human-readable name and blurb for the cluster, e.g. "EU AI Act enforcement delays" — what the user actually sees.
keywordsTEXT[]top terms from cluster headlinesExtracted terms passed into the labeling prompt so the LLM has concrete signal, not just volume counts.
centroidVECTOR(768)mean embedding of member news articlesThe cluster's center point in embedding space — lets new Reddit posts be assigned here by nearest-neighbor search instead of full re-clustering.
representative_article_idUUID→ articles.id, on delete set nullThe single news article closest to the centroid — shown to users as "here's what this sub-theme is about."
first_seen_at / last_seen_atTIMESTAMPTZdefault now()When the cluster first appeared, and the most recent discovery run it was still present in.
label_generated_atTIMESTAMPTZ—When the label/description were last (re)generated by the LLM.
volume_at_last_labelINTdefault 0 — relabel baselineArticle + Reddit volume as of the last labeling call — a relabel only fires once growth against this baseline crosses the configured threshold.
statusTEXTdefault 'emerging', check in (emerging, active, declining, inactive)Lifecycle stage of the sub-theme, driven purely by volume thresholds run over run.
created_at / updated_atTIMESTAMPTZupdated_at trigger-maintainedWhen the row was created and last modified.
idx_sub_themes_topic_id idx_sub_themes_status idx_sub_themes_centroid — ivfflat, cosine, lists=10 trigger: sub_themes_updated_at

sub_theme_memberships

intelligence

Current state only, not history — every discovery run deletes and replaces all rows for a topic. membership_type distinguishes articles that formed the cluster (news, via HDBSCAN) from posts assigned afterward (reddit, via nearest centroid).

ColumnTypeConstraintsWhat it means
idUUIDprimary keyIdentifies this one article-to-sub-theme assignment.
sub_theme_idUUID→ sub_themes.id, cascadeWhich sub-theme this article currently belongs to.
article_idUUID→ articles.id, cascadeThe article (news piece or Reddit post) that's a member.
membership_typeTEXTcheck in (news, reddit)Whether this article helped form the cluster via HDBSCAN (news) or was assigned afterward by nearest-centroid similarity (reddit).
similarity_to_centroidFLOATcheck -1–1Cosine similarity to the sub-theme's centroid — the news article with the highest value becomes the representative_article_id.
created_atTIMESTAMPTZdefault now()When this membership row was written by the current discovery run.
unique (sub_theme_id, article_id)idx_stm_sub_theme_ididx_stm_article_id

sub_theme_snapshots

intelligence

Time-series: one row per sub-theme per discovery run. Feeds evolution detection, the rolling sentiment baseline, and the timeline API. label/description are frozen copies, so an old snapshot keeps the wording that was live then even after a relabel.

ColumnTypeConstraintsWhat it means
idUUIDprimary keyIdentifies this one point-in-time snapshot.
sub_theme_idUUID→ sub_themes.id, cascadeWhich sub-theme this snapshot measures.
topic_idUUID→ topics.id, cascadeDenormalized parent topic — lets the timeline API filter by topic without a join through sub_themes.
article_countINTdefault 0 — news articles in clusterHow many news articles were in the cluster at this run.
reddit_post_countINTdefault 0 — assigned by centroidHow many Reddit posts were assigned to it at this run.
total_volumeINTdefault 0 — sum of the two aboveCombined volume — the number growth and decline detection actually watches.
sentiment_scoreFLOATcheck -1–1, null if no Reddit signalUpvote-weighted VADER compound score over this run's Reddit comments — the input to the sentiment-shift alert.
statusTEXTcheck in (emerging, active, declining, inactive)The sub-theme's lifecycle stage as it stood at this exact run.
label / descriptionTEXTfrozen at snapshot timeCopy of the sub-theme's wording as of this run, so a later relabel doesn't rewrite history.
snapshot_atTIMESTAMPTZdefault now()When this snapshot was recorded — the axis the timeline view plots against.
idx_sts_sub_theme_id idx_sts_topic_id idx_sts_snapshot_at desc idx_sts_sub_theme_snapshot_at (composite)

intelligence_alerts

delivery history

Kept separate from alerts on purpose — folding it in would force article_id to go nullable and pile on CHECK constraints. These fire on sub-theme state changes, not individual articles; payload is a JSONB snapshot so the alert still reads correctly even if the sub-theme keeps evolving after it's sent.

ColumnTypeConstraintsWhat it means
idUUIDprimary keyIdentifies this one intelligence alert.
user_idUUID→ users.id, cascadeWho receives it.
topic_idUUID→ topics.id, cascadeWhich topic the sub-theme belongs to.
sub_theme_idUUID→ sub_themes.id, cascadeThe sub-theme whose state change triggered this alert.
sub_theme_snapshot_idUUID→ sub_theme_snapshots.id, cascadeThe exact snapshot whose numbers crossed a threshold — also the idempotency key that stops a replayed Kafka message from double-firing.
alert_typeTEXTcheck in (sub_theme_emerging, sub_theme_growing, sub_theme_disappearing, sub_theme_sentiment_shift)Which of the four detectable events this is — decides the wording and urgency of the notification.
channelTEXTcheck in (email, sms, websocket)How this particular alert was delivered.
statusTEXTdefault 'pending', check in (pending, sent, failed)Delivery outcome, same purpose as on the core alerts table.
payloadJSONBnot null — state snapshot at alert timeFrozen copy of the sub-theme's label, volume, sentiment, and status at send time, so the alert reads correctly even after the sub-theme keeps evolving.
sent_atTIMESTAMPTZ—When delivery succeeded, null until then.
created_atTIMESTAMPTZdefault now()When the alert was generated.
unique (user_id, sub_theme_snapshot_id, alert_type, channel) idx_ia_user_id_created_at idx_ia_status idx_ia_sub_theme_id
